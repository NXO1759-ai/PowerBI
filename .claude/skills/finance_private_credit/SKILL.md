# Finance private credit

## When to Apply
- Editing `frontend/credit.html`, `frontend/credit.js`, `frontend/credit-{stress,capital,dealflow}.js`, `frontend/credit-underwriting.js`, `frontend/credit-lenders.js`, `frontend/credit-lenders-drilldown.js`, `frontend/lib/{credit,lenders-scorecard,pc-series,credit-terms}.js`, or any `frontend/*credit*.css` / `lenders-scorecard.css`.
- Editing `scripts/refresh-bdc.mjs`, `scripts/build-bdc-terms.mjs`, `scripts/build-underwriting-panel.mjs`, `scripts/ingest-pc.mjs`, `scripts/build-credit-terms.mjs`, or `scripts/lib/{bdc-concepts,bdc-composite,bdc-prose,soi-parse,soi-html,rpage,zip-stream,zip-read,ooxml,pptx-charts,xlsx-read,pc-map,pc-series,pc-periods,fred,github-actions,ratelimit}.mjs`. The deck and workbook readers (`pptx-charts`, `xlsx-read`, `ooxml`, `zip-read`) are imported only by `ingest-pc.mjs` and the pc tests and fixture builders; `fred.mjs` is imported only by `api/credit-macro.js` and `api/macro.js`.
- Editing the credit-layer routes `api/{bdc-pull,rebuild,price-history,credit-macro,macro,fsa-note,comps}.js`, `vercel.json`, `.github/workflows/ingest-pc.yml`, the credit steps of `.github/workflows/smoke.yml`, or the `layer` input in `.github/workflows/weekly-refresh.yml`.
- Touching `frontend/data/bdc/*`, `frontend/data/underwriting.json`, `frontend/data/pc/*`, or `scripts/pc-map.json`.
- Symptoms: a leverage ratio built from two different filing periods; a "0" where the filer disclosed nothing; a BDC's schedule missing with no stated reason; a composite figure printed without its n; a chart's numbers changing because a deck's chart numbering moved; the owner Rebuild control failing with a wording the server never sent.

## When NOT to Apply
- The operating-company fact pull, dedupe, the NCI tie, the staleness guard -> `finance_sec_edgar_pipeline` (`scripts/refresh.mjs`, `scripts/lib/sec-pull.mjs`, `statements.mjs`).
- Defining or changing how a ratio is computed -> `finance_metric_parity`; credit formulas live in `frontend/lib/credit.js` (`CREDIT_VERSION`) and `frontend/lib/ratios.js`, and are imported, never re-derived in a page. One exception: `bdcDistance` in `frontend/lib/valuation.js` and the `opts.distance` callback on `selectComparables` are credit-only - their callers are `frontend/credit-lenders.js` and `scripts/test-bdc-peers.mjs`, which pins them, and `finance_metric_parity` says nothing about BDCs. Those two stay with this skill; the rest of `valuation.js` goes to `finance_metric_parity`.
- The other dashboard pages (FSA, strategy, valuation, risk registers, news) and the terminal UI conventions -> `finance_analysis_features`. Two cautions on that hand-off: its Procedure D still says `credit.html` is a placeholder ("The credit view is in build"), which has not been true since this terminal shipped - read that sentence as stale and this skill as the current one; and it claims `api/fsa-note.js` and `api/macro.js` in its own When to Apply (it does not claim `api/comps.js` at all). For the credit-layer use of those three routes - `fsa-note` kinds `credit` and `underwriting`, and `macro` and `comps` as `credit.js` and the Lenders view call them - this skill is the owner.
- The pipeline view of the BDC leg -> `finance_sec_edgar_pipeline` Procedure D, which is a pointer of a few lines: which builders go through `sec-pull.mjs`'s 125 ms gate and which do not. Every detail of the leg - the monthly SEC data-set zips, the frames reconciliation, the `MIN_FRAME_FILERS` guard, the holdings gate and the `weekly-refresh.yml` layer gate - lives here and here only. If a fact ever appears in both, cut it from the sibling rather than editing both copies.

## Instructions
Reference: see _references/powerbi-code-map.md for the current route/API/workflow map.

House facts:
- Five builders feed this page and none of them is named `build-bdc-data`, `build-bdc-holdings` or `build-pc-series`: they are `scripts/refresh-bdc.mjs` (the BDC layer, holdings stage included), `scripts/build-bdc-terms.mjs`, `scripts/build-underwriting-panel.mjs`, `scripts/ingest-pc.mjs` and `scripts/build-credit-terms.mjs` (the generated `frontend/lib/credit-terms.js`, Procedure A.5). There is no `api/pc-series.js` - `frontend/lib/pc-series.js` reads the committed files under `data/pc/` directly.
- Never name an AI vendor, model or product anywhere on this page or in its prompts. `api/fsa-note.js` force-signs every credit note `"— the research model"` (`SIGNATURE`), and `frontend/credit.html` says the same in prose.
- SECURITY NOTE (do not copy the value): `api/macro.js` carries a hardcoded fallback FRED key, acceptable only while the repo is private. The credit page calls `/api/macro` on every forced refresh, so any "make the repo public" task must rotate it to `FRED_API_KEY` first.

### Procedure A - the page and its four views
1. `frontend/credit.html` loads plain classic scripts in a fixed order: `lib/http.js`, `metrics.js`, `ratios.js`, `export.js`, `metric-catalog.js`, `lib/credit-terms.js`, `lib/credit.js`, `lib/valuation.js`, `vendor/chart.umd.min.js`, `lib/pc-series.js`, then `credit.js`, the three Market section files, `credit-underwriting.js`, `lib/lenders-scorecard.js`, `credit-lenders-drilldown.js`, and `credit-lenders.js` last. `RTCatalog` must precede every file that registers into it, and the three Lenders files must precede `credit-lenders.js`, which mounts them. `scripts/test-nav.mjs` fails a page that references a script absent from disk.
2. `VIEWS = ["market","lenders","underwriting","glossary"]` in `credit.js`; `setView()` toggles `#<view>-view.hidden`, sets `aria-pressed` on `#view-<view>` and writes `?view=<v>` with `history.replaceState`. Market is static markup plus three mounted sections; the other three views mount lazily on first entry.
3. Market's three ingested sections register onto `window.RTCreditSections` and mount in `SECTION_ORDER = ["stress","capital","dealflow"]`. The contract, written out in `credit.js` itself, is `{ id, title?, groups, mount(container, ctx) -> Promise<void>, CAPTIONS, facts?(ctx) -> string[], keys? }`. `credit-dealflow.js` also pushes `KEYS` and `model` of its own; neither is part of the contract and `credit.js` reads neither, so do not add either to a new section expecting the page to use it. `credit.js` loads before them, so everything that needs them goes through the `SECTION_SCRIPTS_READY` promise (resolved on `DOMContentLoaded`). A planned container with no registered section renders `data-section-status="missing"`, never an empty tile.
4. `RTCatalog.register()` is one flat namespace and is all-or-nothing: a duplicate key throws and the whole batch is lost, which in a parser-blocking script means the file's IIFE aborts and its global (`RTLendersView`, `RTCreditUnderwriting`, `RTLendersDrilldown`) never gets assigned. Keep the per-file prefixes - `credit-stress.js` (`m1*`/`m4`-`m6`, `stressPanel`, `pcPriceLcd`), `credit-capital.js` (`cap*`), `credit-dealflow.js` (`df*`), `credit-underwriting.js` (`u1`-`u4`, `uw*`), `lib/lenders-scorecard.js` (`lenders*`), `credit-lenders-drilldown.js` (`lendersDrill*`), `credit-lenders.js` (`lendersComposite*`, `lendersDispersion`, `lendersPeers`). `scripts/test-lenders-view.mjs` asserts no collision across the three Lenders files in the real load order.
5. `frontend/lib/credit-terms.js` is generated - `node scripts/build-credit-terms.mjs` from `frontend/data/pc/glossary.json` (299 terms, glossary dated 2026-09-11). Edit the JSON, re-run, commit both. The generator's `validate()` throws rather than writing on a missing field, a popup over `POPUP_MAX = 240`, a `kind` outside `["series-id","acronym","instrument","metric","market","regulation"]`, a `side` outside `["market","lender","both"]`, or a colliding alias. Output is deterministic (the date comes from the JSON, not the clock), so `scripts/test-credit-terms.mjs` can require the committed file to be byte-identical to a fresh run.
6. `CREDIT_VERSION` is declared once, `frontend/lib/credit.js:44` (`"1.1.0"`), re-exported by `scripts/lib/bdc-composite.mjs` and stamped into `composite.json`. Bump it whenever a formula in `lib/credit.js` changes, and update the pin in `scripts/test-credit-ratios.mjs` in the same change.
7. Every number the three Market sections draw comes from `window.RTPcSeries` (`frontend/lib/pc-series.js`) over the committed files under `frontend/data/pc/` - `series-index.json`, `series/<group>.json` per group asked for, `restatements.json`, `series-provenance.json`. Static files only (`BASE = "data/pc/"`); there is no endpoint. Nothing is typed into a section from a report. Three rules govern what may be drawn:
   - **Grain.** A point is `{ p, g, v }` - `p` the period end `"YYYY-MM-DD"` (null on a press point whose period names no calendar date, and then `g` is `"label"` and `label` says which), `g` one of `quarter`, `half`, `year`, `ytd`, `month`, `asof`, `rolling3m`, `rolling6m`, `rolling12m`, `window`, `label`, `v` the value in the key's own unit. Windows carry `start`; a snapshot point carries `c`, the bucket or sector, and several points then share one `p`. **Rolling, window and year-to-date points are never summed with quarters or years.** A new tile that totals a series must filter on grain first.
   - **Alias.** A key carrying `alias` is a duplicate deck series stored once under the named key and holds no points of its own; resolve it before reading points. A key carrying `table` is a list sheet whose rows live under `data/pc/<table>`.
   - **Stale.** A key whose group failed to match in the newest edition keeps its last points and is flagged `stale`. It is not an error and it is not dropped - but a page drawing a stale key must label it as such, with its edition and as-of, rather than presenting it as current.
8. The page's whole fetch layer is `getJson(path, subject, force)` in `credit.js`; changing it changes three things that are easy to break silently.
   - **Fixture mode.** `?fixture=1` sets `FIXTURE` and `getJson` reads `data/pc/fixtures/<file>` instead of any endpoint, mapped by `fixtureFile()`: `/api/credit-macro` -> `credit-macro.json`, `/api/macro` -> `macro.json`, `/api/price-history?ticker=T` -> `price-history-<T>.json`. Five replies are committed (`credit-macro`, `macro`, `price-history-{BIZD,BKLN,SRLN}`). This is the only way to work on the Market view with no keys and no egress, so **a new endpoint the page calls needs a committed fixture and a `fixtureFile()` branch in the same change**, or fixture mode silently returns nothing for it. `FIXTURE` is also passed into `RTLendersView.mount()` and appends `" · fixture data"` to the status line.
   - **Where `/api` comes from.** `API_BASE`, declared in the same block: the deployed site serves `/api` beside the page, a localhost session usually does not, so `API_BASE` probes `rt-dev.js` with a HEAD request and falls back to `PROD = "https://www.chineduokeke.mba"` when that probe fails. **A localhost page with no dev server running silently reads production** - fine for looking at the page, wrong for testing an endpoint change.
   - **The forced path.** `load(force)` writes the status line "Refreshing every feed, skipping the six-hour cache…", calls `window.RTPcSeries.invalidate()`, and appends `force=1` to each endpoint call so the six-hour warm caches are skipped. `var keep = force && DATA.cm` is the rule that matters: **a forced refresh that is refused or fails leaves what is already drawn standing** - only a first load shows the empty state - and a 429/403 renders the refusal sentence ("it is limited to a few a minute and to the terminal's own pages. The series already on the page stay as they were."). Do not change that to a blank view.
9. **Working on the page locally.** `cd frontend && npm run dev -- --port 7240`. `frontend/package.json`'s `dev` script is `node dev-server.js`; `dev-server.js` serves the static pages and every `/api/<name>` in-process by importing `api/<name>.js` and calling its default export, and it is the only server that answers `rt-dev.js`, which is how `API_BASE` learns `/api` is local. **Pick a port deliberately: the default is 7100 and 7100 is not on the rate limiter's origin allowlist.** `scripts/lib/ratelimit.mjs` allows only `http://localhost:{7240,7241,7242}` and the `127.0.0.1` equivalents beside the two production origins, and `dev-server.js` passes the browser's real headers straight through, so on 7100 every `sameOrigin: true` path - `/api/credit-macro?force=1`, `/api/price-history?force=1`, `/api/rebuild` - answers 403 with "this endpoint serves the research terminal only" (Procedure E.2). `?fixture=1` sits on top of either arrangement and is the no-egress path.

### Procedure B - the BDC data leg
1. `node scripts/refresh-bdc.mjs [--ticker T[,T]] [--limit N] [--out DIR] [--quarter CY2026Q2] [--holdings-only|--skip-holdings|--composite-only] [--force-holdings] [--source dataset|instance] [--cache DIR]` writes six kinds of file under `frontend/data/bdc/`: `universe.json` (the `"814-"` file-number rule, 53 rows), `company-<TICKER>.json` (quarterly `series` plus `disclosed`, every value carrying `tag`, `periodType`, `start`/`end`, `form`, `filed`, `accn`, `source`), `holdings-<TICKER>.json`, `composite.json`, `coverage.json` and `refresh-report.json`. It reads `terms.json`; it does not write it.
2. Inputs: SEC companyfacts and frames through `scripts/lib/sec-pull.mjs`; the SEC's monthly BDC data set zips (`<YYYY_MM>_bdc.zip`, streamed by `scripts/lib/zip-stream.mjs` into the gitignored `.cache/bdc/datasets/`); the filing's own `-xbrl.zip` instance when no monthly zip carries the schedule; the main inline-XBRL document (`.cache/bdc/docs/`) for `scripts/lib/soi-html.mjs` and `scripts/lib/bdc-prose.mjs`; and the `FilingSummary.xml` R page via `scripts/lib/rpage.mjs` as a second reading of non-accrual and industry. Every SEC request goes through the one 125 ms slot gate in `sec-pull.mjs` (`SEC_MIN_INTERVAL_MS`; `paced()` reserves its slot synchronously so concurrent callers queue instead of firing together). Never add a parallel unthrottled path. Two properties of those inputs govern everything downstream:
   - **Nothing is buffered.** `2026_08_bdc.zip` is 265.6 MB on the wire and its `num.tsv` inflates to 1.17 GB (probed 2026-09-11), so `zip-stream.mjs` reads the central directory from the tail, serves a member as a stream over its byte range and hands the caller lines. A change that reads a member whole will run the machine out of memory. Downloads go one at a time to a `.part` file renamed on completion, never resumed, and are skipped when a HEAD says the remote matches the copy on disk; SEC's files host sends `Content-Length` and `Last-Modified` but no ETag, so a missing header is treated as "unknown", never as "changed".
   - **Companyfacts can lag, so never call a period the latest one on companyfacts alone.** The cadences differ: companyfacts is continuous per filer, the data set is monthly, and XBRL frames can run ahead of companyfacts by weeks (ARCC's Q2 2026 sat in frames on the morning of 2026-09-10 and in companyfacts only that evening). `mergeFrames` adds or fills any period newer than anything companyfacts holds for that concept, stamps `source: "frames"` and leaves form and filed null; an equal or older period keeps its companyfacts value. Reconcile against the frames or the filing instance first. The guard the other way is `MIN_FRAME_FILERS = 100` (B.6).
3. `scripts/lib/bdc-concepts.mjs` holds `BDC_CONCEPTS` - 39 concepts - plus `buildBdcSeries` and `mergeFrames`; `soi-parse.mjs` reads a schedule into rows and owns the reconciliation gate; `soi-html.mjs` reads the printed schedule out of the filing's HTML; `rpage.mjs` reads the rendered R page; `bdc-composite.mjs` pools the passed filers.
4. The holdings gate is the rule to respect above all: rows are reconciled against `InvestmentOwnedAtCost` and `InvestmentOwnedAtFairValue` within `GATE_TOLERANCE = 0.005` (`soi-parse.mjs`, `reconcile()`). The gate tries variant row sets in order and the first that reconciles wins; every set tried is recorded in `gate.tried`. **A filing that fails gets no holdings file at all** - the refusal and its sums go to `refresh-report.json` and `coverage.json`. The committed `coverage.json` records 32 passed and 21 refused; the page reads that list and prints "not yet parsed" for a refused filer, never "not disclosed". A schedule that will not reconcile is a refusal, not a bug to be fixed by loosening the gate: Saratoga still fails after every variant set (its cost sum is 4.6% under its own tag, and sixteen rows carry a cost and no fair value), and that is the designed outcome.
5. `composite.json` states `weighting` in prose and carries `n` per figure (`composite.n.<key>`), `members` (32), `dispersion`, `priceToNavP25` and `creditVersion`. Dollar figures pool as Σ numerators ÷ Σ denominators; `assetCoverage` and `opexRatio` are means weighted by each member's cost of third-party debt. Never print a composite figure without its own n - the tile's n and the dispersion row's n are computed on different bases and each states its own.
6. Two refusal habits the refresh already has, to preserve: a filer EDGAR did not answer for is **not** removed from the universe (a failed submissions or roster call skips the whole removal pass for that run), and `PARTIAL = Boolean(ONLY || LIMIT)` means a `--ticker`/`--limit` run writes company files but never a `coverage.json` that would count the rest of the universe as missing. `MIN_FRAME_FILERS = 100` guards against reading a quarter whose 10-Q wave has not landed. Exit codes: 0 if at least one company file was written, 1 if none, 2 if the pull failed.
7. `node scripts/build-bdc-terms.mjs [--out FILE] [--offline]` writes `frontend/data/bdc/terms.json` from each filer's latest 10-Q/10-K prose (`bdc-prose.mjs`): `{ sbaExempt, fees, targetLeverage, statutoryCoverage }` per ticker, 53 filers. **A full run replaces the file; it does not merge.** `--out` defaults to the committed `frontend/data/bdc/terms.json`, and `const filers = previous && (ONLY || LIMIT) ? {...previous.filers} : {}` means only a `--ticker` or `--limit` run starts from what is already there. A full run without those flags starts empty, and `--offline` pushes any filer whose document is not in the gitignored `.cache/bdc/docs/` onto `skipped`, so a full offline run over a partly warmed cache would write a terms.json holding only the cached filers over the committed 53 - silently, because `terms.json` is read downstream by `refresh-bdc.mjs` and by `lib/lenders-scorecard.js` for the statutory line and the fee card. Only the all-empty case is caught, by the `if (!Object.keys(filers).length) return 1` guard. So: only a `--ticker` or `--limit` run may write to the committed path; any other run passes a scratch `--out`. A sentence the document does not carry stays **null** - nothing is typed in from memory, and every value carries the sentence and the accession it came from. A filer whose document says it is internally managed gets no fee rates at all. The SBA seed stays `"unconfirmed seed"` until the filer's own document confirms it.
8. **Adding a fortieth concept**, in order:
   1. Add the tag ladder to `BDC_CONCEPTS` in `scripts/lib/bdc-concepts.mjs`.
   2. Decide whether it also belongs in `OVERLAY_CONCEPTS` in `api/bdc-pull.js` - the hand-maintained six the live one-BDC route asks frames for. Only a 3M-span or instant concept can ever merge: `mergeFrames` rejects every frame row whose `spanClass` is not `"3M"`, which is why `niiPerShare`, a year-to-date duration concept, is deliberately left out. Adding a year-to-date concept there spends budget on a call that can never merge.
   3. Confirm the key reaches `coverage.json`'s `metrics` block, which `buildCoverage` keys off `Object.keys(BDC_CONCEPTS)` and which mirrors the ladder one for one (39 today). A `--ticker` or `--limit` run writes no `coverage.json` at all (B.6), so this needs a full run to a scratch `--out` - `node scripts/refresh-bdc.mjs --out .cache/scratch-bdc` - never to the committed directory.
   4. Run `node scripts/test-bdc-series.mjs` and `node scripts/test-bdc-data.mjs`. Both read `BDC_CONCEPTS` directly, so there is no separate acceptance list to edit.

### Procedure C - the Underwriting leg
1. `node scripts/build-underwriting-panel.mjs` writes exactly one file, `frontend/data/underwriting.json` (`OUT_FILE`, not overridable by a flag): `{ schemaVersion: 1, source, n: 137, coverage, companies }`, where `companies` is an object keyed by ticker. Input is live companyfacts per covered ticker (this script has its own `paced()` at 130 ms, not `sec-pull.mjs`'s), the universe from `frontend/data/{company-index,coverage,industry-map}.js`, statements from `scripts/lib/statements.mjs` and ratio blocks from `frontend/lib/ratios.js`.
2. **No company is ever dropped.** A ticker that fails still gets a row with every figure null and the reason as the first entry in `notes`. Exit codes: 0 if at least one row has a usable period, 1 if every row is null, 2 if the universe could not be resolved.
3. The S&P bands: `SP_FINANCIAL_RISK_BANDS` lives in `frontend/lib/ratios.js` (Minimal < 1.5x, Modest 1.5-2, Intermediate 2-3, Significant 3-4, Aggressive 4-5, Highly leveraged 5x+ on debt/EBITDA); `FFO_DEBT_BANDS` is local to the builder and runs the opposite direction (Minimal >= 60%, ... Highly leveraged < 12%), because higher FFO/debt is safer and cannot share `bandDistance`'s ascending-worse walk. Covenant headroom walks **gross** debt/EBITDA, the same measure the headline placement uses, so the two labels agree.
4. `SECTORS_WITHOUT_CORPORATE_LADDER = new Set(["Financials","Real Estate","Utilities"])`. Those rows get a stated `sectorCaveat` and **no** band placement, no covenant headroom, no leveraged-lending sub-ladder and no cost-of-debt fallback. The caveat must be passed into `buildRow` by the caller; see the pitfall below. Excluded names are still plotted on the U1 scatter with a distinct marker and captioned as excluded, so "137 covered companies" stays true.
5. One reason string, `leverage.leverageNotComputableReason`, is resolved in order: the sector caveat; EBITDA not computable; EBITDA <= 0; the debt-total trust gate. The view reads that string rather than re-deriving "why" from a sign check of its own.
6. Maturity ladder: null with a reason, never a zero. An untagged filer gets `"no maturity schedule tagged"`; an LTM period with no ladder falls back to the latest annual ladder, carrying `asOf` and a note that it came from the 10-K and was not retagged in the quarter.
7. Revolver capacity is rare among operating companies (6 of 137 tag it) and is named in `notes` when it is treated as 0. Liquidity runway is the page's one deliberate exception to the refusal rule: `add()` tolerates a missing term, the numerator is stated as a floor, and every zeroed term is named - but the runway is still **refused outright** unless cash, next-twelve-month maturities and the one-year lease figure all resolve, and a non-positive runway is withheld rather than printed as a negative multiple.
8. Cost of debt: the tagged rate first; else suppressed entirely for the excluded sectors; else interest expense over average debt from the **same series** (annual-to-annual or LTM-to-LTM), refused above `COST_OF_DEBT_CEILING = 0.15` with a note naming the computed figure; else one of four "not disclosed" notes naming the actual missing input.
9. Fixed-charge coverage records why it was not computed and distinguishes "cash interest paid is not tagged" from "tagged in some periods, but the trailing-twelve-month sum is incomplete". Cash taxes are stated as proxied by the accrual `IncomeTaxExpenseBenefit`, with a second note when that line was a benefit. FFO is stated as net income plus D&A, not S&P's fuller bridge.

### Procedure D - the Lenders leg
1. `frontend/lib/lenders-scorecard.js` builds one row per universe ticker from `company-<TICKER>.json`, `terms.json`, `coverage.json`, the holdings file where one exists and `/api/comps` for price. Every field a source cannot answer is **null** - never 0, never NaN - and `naTd()` renders it with a label (`"not disclosed"`, or `"not yet parsed"` for a ticker in `coverage.holdings.tickers_refused`) and the reason in the `title` attribute. `sources` records which tag-ladder step answered each ambiguous field - debt, the two NII lines, distributions per share, asset coverage - so a reader can tell a tagged figure from a prose or formula fallback. Debt runs a four-tag ladder plus an instance-level fallback; a single-facility tag (`LineOfCredit`) is never treated as total debt. **Price is derived, not fetched**: `/api/comps` carries no price field, so the view computes price as marketCap / sharesOutstanding. A row missing either figure has no price, and therefore no price/NAV, no dividend yield and no p25 stripe.
2. `periodMismatch(keys)` gates every cross-field ratio: mark (`portfolioFairValue`/`portfolioCost`), debt/equity, net debt/equity and dividend coverage are computed only when their inputs share a filing period, and otherwise show not disclosed with `"... are different filing periods"` named on hover. Add a ratio here only behind the same gate.
3. Three severity flags fire as a stripe (asset-coverage cushion under 15% via `RTCredit.assetCoverageCushion` against the statutory line `terms.json` states, non-accruals over 3% of cost - holdings-only, and price/NAV below the 25th percentile of the priced rows in this universe, computed in `buildRows()` from every row's own `priceToNav` once they are all known). `composite.json`'s `priceToNavP25` is **not** an input to the scorecard - it is not part of the module's input contract, it currently ships null, and any cross-check against it belongs to the caller or the build script, not to `lenders-scorecard.js`. The blueprint's fourth reading - regular dividend coverage under 1.0x for two consecutive quarters - cannot be confirmed from a combined distributions-per-share figure and is surfaced as a **note on the cell, never a stripe**; the note also requires the newer of the two quarters to be the filer's own latest filed quarter.
4. `frontend/credit-lenders.js` owns L10 (the composite strip, read straight off `composite.json`'s `weighted`/`n`/`dispersion` - nothing recomputed in the page), L11 (the dispersion dots) and the 4.5 peers panel. A dispersion-sourced tile with n = 0 prints `"not yet computed"` rather than a number. The whole view is mounted through `RTLendersView.mount(ctx, {force})` and cached on `STATE`; `{force:true}` clears data, pending, error, `openTicker` and `peersSubject` and re-fetches. **Its four core fetches sit in two deliberate lanes, and a new fetch goes into one of them on purpose.** `universe.json` and `coverage.json` are mandatory: either failing throws (`"universe.json carries no rows"`, `"coverage.json did not answer"`) and a page-level error state replaces the whole view, because a half-rendered table is worse than a stated failure. `terms.json` and `composite.json` are best-effort and resolve to null - a terms build that has not run, or a holdings release that has not landed, is a designed empty state downstream, never a page fault.
5. BDC peer selection is `RTValuation.selectComparables(subject, candidates, { distance: RTValuation.bdcDistance, keep: 8 })` - the BDC-specific distance, not the operating-company one. `scripts/test-bdc-peers.mjs` pins it, including the case where no usable SIC in `universe.json` forces the pool to fall through to every covered company.
6. `frontend/credit-lenders-drilldown.js` registers twelve `lendersDrill*` catalog keys and renders L1 (NAV vs price), L2 (dividend coverage), L3 (leverage vs the statutory line), L4 (spread histogram), L5 (maturity wall), L6 (sector mix), L7 (mark and stress), L8 (holdings table plus a hidden export table), L9 (watchlist), L12 (return decomposition), plus a liability card and a fee card. It registers `{open, close, CAPTIONS}` and throws on a second registration into the same catalog. A refused ticker renders that ticker's own refusal reason and "not yet parsed" in the holdings-only panels.
7. The Lenders view deliberately batches `/api/comps` twelve tickers a call - `chunk(tickers, 12)`, `api/comps.js`'s own ceiling (`.slice(0, 12)`) - instead of 53 separate `/api/market` calls, so a 53-row universe costs five calls, not 53. One bad batch never fails the others or the page. It also skips the holdings file for a refused ticker so a load does not produce a 404 storm. `scripts/test-lenders-view.mjs` asserts both; its single `/api/comps` call is the six-ticker fixture fitting under the ceiling, not a one-call rule.

### Procedure E - the serverless layer and the owner rebuild
1. Seven endpoints serve this page: `/api/credit-macro`, `/api/macro`, `/api/price-history`, `/api/fsa-note`, `/api/comps`, `/api/rebuild`, and `/api/bdc-pull` - which is complete and tested (`scripts/test-bdc-pull.mjs`) but not yet called from anywhere under `frontend/`; both its own header and the comment in `credit.js` say the Lenders drill-down is expected to wire it. `/api/market` is not a credit endpoint. Every one is wrapped in `jsonSafe()` from `scripts/lib/handler.mjs`, which answers 500 with the endpoint's own sentence and `Cache-Control: no-store` rather than letting the platform serve an HTML error page.
2. Rate limiting is `gate()` from `scripts/lib/ratelimit.mjs`: same-origin allowlist (403), per-caller token bucket (429), daily cap charged only when `cost > 0` (429). **An unnamed call site shares one bucket and one global daily counter with every other unnamed call site on that warm instance.** An endpoint that spends real money - SEC, FRED or GitHub calls an unauthenticated caller should not be able to run up - passes a `name` distinct from every other gated endpoint's. Named buckets in use: `rebuild-post` (burst 2, 1/min), `rebuild-get` (burst 3, 3/min), `bdc-pull` (burst 2, 3/min, cost 1), `price-history-force` (burst 3, 4/min). All gate state is per warm instance; it blunts a script, it is not a guarantee. **One FRED-spending path is gated but unnamed**, so know it before you read it as a bug: `api/credit-macro.js` guards its own `?force=1` with `gate(req, { burst: 3, ratePerMin: 2, cost: 0, sameOrigin: true })` - no `name`, so it shares the unnamed bucket with every other unnamed call site on that instance - and that path reaches FRED 22 times, which is the traffic the page forces on every refresh. `cost: 0` keeps it off the shared daily counter and `sameOrigin: true` keeps it to the terminal's own pages, so it is not open to an anonymous caller; whether the missing name is deliberate is **not recorded anywhere in the repo**. Raise it as its own change rather than renaming the bucket inside a feature PR, and do not cite it as precedent for a new unnamed money-spending call site.
3. `api/bdc-pull.js`: `maxDuration = 60`, one wall-clock `DEADLINE_MS = 40000` for companyfacts plus every frame call, `FRAME_TIMEOUT_MS = 8000` per frame, `QUARTERS_KEPT = 8`. The overlay loop checks the remaining budget before each concept and each ladder rung and breaks with `truncated: true` rather than being killed at `maxDuration`. A timeout answers 504 with its own sentence, never 404 - the `TIMED_OUT` symbol exists so a timeout is never misreported as "EDGAR has nothing for this CIK". It `readFileSync`s `frontend/data/bdc/universe.json`, which is the only reason `vercel.json` carries a `functions.includeFiles` entry; move or rename that file and the entry moves with it.
4. `api/rebuild.js` is the owner control. **Two environment variables an owner must set: `GITHUB_DISPATCH_TOKEN`** (fine-grained, Actions read/write on this one repository) **and `REBUILD_SECRET`** (the value pasted into the modal). If either is missing or empty both verbs answer **503 `{ error: "rebuild is not configured" }` before the rate gate, the secret check and any GitHub call** - which is also what stops the smoke suite from ever dispatching a real run. `OWNER`, `REPO`, `WORKFLOW_FILE` and `REF` are hard-coded public information, not credentials.
5. The secret travels only as the `X-Rebuild-Secret` header, never a query string, and is kept in `sessionStorage` (not localStorage) to cap the lifetime of a compromise. `secretMatches()` SHA-256 hashes both sides to a fixed 32 bytes before `timingSafeEqual`, so no length branch leaks. POST accepts `{ layer?: "all" | "bdc" }` - `LAYERS = ["all","bdc"]`, `"pc"` deliberately withheld because `weekly-refresh.yml` has no PitchBook/LCD step - and answers 202, or 401/400/409/502 with its own sentence. GET polls with `?since=<ISO>` minus 5000 ms of clock skew, and both verbs race a 25 s `DEADLINE_MS` inside `maxDuration = 30`. The page renders **the server's sentence verbatim**; do not paraphrase a status in `credit.js`, because the wording would then drift from the endpoint's.
6. The page half of the owner control lives between two literal markers in `credit.js` - `/* >>> OWNER-TOOLS-BLOCK-START ... */` and `/* <<< OWNER-TOOLS-BLOCK-END */` - because `scripts/test-owner-tools.mjs` slices the source between them and evaluates that block. Moving that code out of the region, or splitting it, breaks the suite even though the page still works. The control itself is hidden: `#owner-btn` stays `hidden` unless a secret is already in this tab's `sessionStorage` or `location.hash === "#owner"`, so open `credit.html#owner` to see it.
7. `weekly-refresh.yml` takes `limit` and `layer` (`all` | `bdc`). **The gate is written as a negative** - five operating-company steps carry `if: ${{ inputs.layer != 'bdc' }}` - because a scheduled run carries no inputs, so `inputs.layer` coerces to `""`; null, `""`, `"all"` and any unrecognized value all take the safe branch and run the full refresh, and only an explicit `bdc` skips them. Keep any new step on the same negative. The BDC and underwriting steps are `continue-on-error`, so a run can conclude "success" with the data step failed - which is exactly why `api/rebuild.js` reads `refresh-report.json`'s `finishedAt` and reports `finishedAtStale`.

### Procedure F - the copy rules the pages follow
1. Popup order is fixed by `showPop()` in `credit.js`: label, `formula`, optional `Caveat`, `definition`, `How to read it`. Every catalog entry carries that field set. A registered key with no catalog entry falls back only to the small local `DEFS` map, so a lost `register()` batch shows as dead hovers.
2. Every section is a one-sentence `<p class="section-blurb">` plus a collapsed `<details class="how-to-read"><summary>How to read this</summary>`.
3. A caption states the finding and the number and stays under 240 characters; the source stamp and the as-of date live in the `.tile-foot` footer, never in the caption. Every `CAPTIONS.<name>` carries a `sample()` holding the widest plausible print, and the offline tests measure it.
4. A missing figure reads `"not disclosed"` (the company did not say), `"not yet parsed"` (the filer's schedule failed the gate), `"not computable without a live quote"`, `"no maturity schedule tagged"` or a named deployment gap - never a zero. A keyless `/api/comps` deployment (503) is labeled a deployment gap, not reused as "not disclosed", which is a statement about the company.
5. Every composite figure states its own n, and the population when the n is not the whole universe.
6. Numeric surfaces carry `font-variant-numeric: tabular-nums`; the credit CSS files already apply it to tiles, ladders, table numbers and `.chart-caption`.
7. A reader-facing string names the source, never the plumbing: no builder script path, no internal blueprint section number. `underwriting.json`'s `source` reads `"SEC EDGAR XBRL companyfacts"` for exactly that reason, after a tile footer once showed readers the builder's own path and a blueprint section number.

### Procedure G - the PitchBook and LCD ingest
1. `node scripts/ingest-pc.mjs [--source DIR] [--out DIR] [--strict]`. It reads every download under the gitignored `data-sources/` tree - the LCD monitor decks under `lcd/<download-date>/`, the Fund Overview exports under `pitchbook/<download-date>/`, the hand-keyed report files under `reports/` - plus the press series already in `frontend/data/pc`, turns each into a vintage of dated series, replays the vintages oldest to newest and writes `frontend/data/pc/`: `series.json`, `series/<group>.json`, `series-index.json`, `series-provenance.json`, `restatements.json`, `tables/<slug>.json` and `ingest-report.json`, plus `data-sources/manifest.json` (sha256, bytes, edition and keys per file read). No network, no dependencies. **It has no step in `weekly-refresh.yml` and runs on the owner's own machine**; `.github/workflows/ingest-pc.yml` runs only the readers, the mapping and the replay against the committed fixture cuts, never the real downloads. The raw decks and workbooks are licensed study material and stay untracked; the workbook's meta block, which names the licensee, is never copied into any output.
2. **Content identifies a chart, never its number.** A monitor's chart number is the order PowerPoint happened to save the parts in, and one inserted slide moves every number after it. `scripts/lib/pc-map.mjs` runs `fingerprint()` over what the reader saw and `match()` against `scripts/pc-map.json`, scoring heading exact 3, series names 2, grain 1, axis formats 1, and the sheet reference weighted 1 whenever the heading signal is absent. A chart is matched only when the best entry **scores at least 4 and beats the runner-up by at least 1**; failing that, a second pass takes an entry only if exactly one is equal on series, grain, formats and sheet reference together. Two entries that tie are ambiguous and the chart is refused with both candidates named - never guessed. Series names that are themselves periods compare by grain, not text. The matcher never edits the map.
3. **Three named refusals** live in `scripts/lib/pc-series.mjs` and each fails a strict build with the chart, slide and key named: `unitMismatch` (the heading matched but the value axis is on another scale than the key's unit - the number would be served a hundred times off under the right label), `duplicateMatch` (two charts of one edition matching the same map group, with nothing to say which one the key means), and a group that failed to match in the newest edition, which leaves every one of its keys `stale` - an accumulating key is spared only when its chart was read and the key merely rolled off.
4. Nothing is dropped, blanked or auto-mapped. A chart or sheet the map does not recognize is written to `ingest-report.json` with its full fingerprint, its previously published key is flagged stale and keeps its last points, and `--strict` exits 1. **Exit codes: 0 clean; 1 under `--strict` with an unmatched chart, sheet or series, a refused point or a filter mismatch - the outputs are still written, with the gap reported; 2 refused before writing anything, or a crash.**
5. The run refuses outright, writing nothing, when a source the committed manifest says has keys has no download in the tree (a fresh clone before the downloads are copied in, or a CI runner, which never sees them), when a deck, workbook or report file cannot be read, or when a report file fails validation - an output written without one of its sources would drop that source's keys silently. To retire a source on purpose, remove its entries from `data-sources/manifest.json` first.
6. The replay is the restatement rule: every vintage is read in order and the newest vintage's value stands per key and date; an older value that differs goes to `restatements.json` with both vintages and editions named. Rolling and year-to-date points are keyed by their window end, so a new edition adds a point instead of overwriting one.
7. **Mapping an unmatched chart** - the one recurring task on this leg, since the matcher never edits the map. In order:
   1. `node scripts/ingest-pc.mjs --strict`. It exits 1 and names what it refused.
   2. Open `frontend/data/pc/ingest-report.json` and copy the refused chart's fingerprint out of it.
   3. Add one entry to `entries` in `scripts/pc-map.json` (213 today). Each entry carries `key`, `source`, `group`, `label`, `unit`, `scale`, `geography`, `population`, `cadence` and `feeds`, plus a nested `fingerprint` of `id`, `heading`, `headingAliases`, `seriesNames`, `grain`, `axisFormats` and `sheetRef`. Copy the fingerprint verbatim from the report rather than retyping the heading.
   4. Re-run without `--strict`.
   5. Confirm the new key appears in `frontend/data/pc/series-index.json` (391 keys across 7 groups) under the group you intended, with the `unit` and `cadence` you gave it - `series-index.json` is what `frontend/lib/pc-series.js` reads, so a key absent from it is not drawable whatever the map says.
   6. `node scripts/test-pc-ingest.mjs`.

## Known pitfalls (from history)
- Only 6 of the 39 BDC concepts populated on a live one-BDC pull -> the response served the frames-merged period verbatim, and `mergeFrames` only sets the concepts it actually merged (`OVERLAY_CONCEPTS` is six), leaving the rest null on that period -> serve `series.latest`, the newest non-null value per concept across kept periods, each value still carrying its own `end` and `source` (`api/bdc-pull.js`).
- A liquidity runway divided a twelve-month maturity by the filer's lifetime lease schedule -> `LesseeOperatingLeaseLiabilityPaymentsDue` is the whole remaining schedule (Amazon's lifetime row is $106.914B against a one-year row of $15.38B) -> `concepts.mjs` carries `opLeaseDueNextTwelveMonths` separately, with the maturity ladder's own 10-K fallback, and the runway is refused rather than computed with the lifetime figure substituted.
- A debt "total" that was really one leg -> `financialLiabilities()` is `add(shortTermDebt, longTermDebt)` and `add()` zero-fills a missing leg, so the result was still a number and published without a note (CVX read 0.01x debt/EBITDA off a $0.401B total against a $30.9B tagged ladder) -> both legs must resolve before the total is trusted; net debt and every ratio built on it are refused with a stated reason otherwise. The same zero-fill made 11 rows read as a confident net-cash position.
- A debt fair-value mark that read as the debt trading at a fifth of face -> `LongTermDebtFairValue` covers the long-term stack and was being divided by the combined debt total -> divide by the same scope the tag covers, and suppress the line when the fair value covers less than 60% of even that narrower base.
- Bank and insurer interest expense read as a cost of debt -> deposit and policy-reserve interest is not corporate borrowing cost, and the interest-over-average-debt fallback cannot separate it -> card 6 is gated by the same `sectorCaveat` as the S&P ladder, and a non-excluded filer above `COST_OF_DEBT_CEILING = 0.15` is refused with the computed figure named.
- Ratios built from two different filing periods -> mark, debt/equity, net debt/equity and dividend coverage each took their inputs from whichever period tagged them -> `periodMismatch()` in `lib/lenders-scorecard.js` returns a "different filing periods" reason and the cell shows not disclosed instead of a cross-period quotient.
- A sector gate that existed in code but never gated -> `buildRow`'s `SECTORS_WITHOUT_CORPORATE_LADDER` exclusion was wired to a `sector` parameter `main()` never supplied, so every bank, insurer, REIT and utility still got a full S&P band placement and covenant headroom -> `classification()` is resolved before `buildRow` and the sector is passed in. When a gate is added, prove it fires on a real row, not only that the branch exists.
- Equity holdings printed in the trillions -> the schedule's principal column is a dollar amount only for a debt row; for equity, vehicle and other rows it is a share or unit count, and it was being formatted as money -> `holdingRow()` publishes `principal` only when `h.t === "debt"`.
- The whole Lenders view scrolled sideways at every viewport width -> `ld-export-only` was put on a `<table>`, whose display box ignores the class's `width: 1px`, so the hidden export table rendered at its full width -> wrap hidden export tables in a block-level `<div class="ld-export-only">`, which does clip. The same round found the visible table being exported as a second, incomplete sheet because the page's export control selects every `table.grid` with or without a name; give each exported table its own distinct `data-export-name`.
- The Underwriting popups quoted tag-coverage counts from a 130-company probe against a 137-row file -> a count measured once during design was pasted into copy -> `coverage` is computed in `build-underwriting-panel.mjs` from the rows the run actually produced, and the page reads that file's own counts rather than a number in a string.
- A site-wide Content-Security-Policy added inside a credit-layer PR -> a header that governs every page of the site does not belong in a change that ships one page -> `vercel.json` carries exactly two keys, `rewrites` and `functions`, and no `headers` block; there is no CSP anywhere in the tree. Keep site-wide headers out of a feature PR and raise them as their own change.
